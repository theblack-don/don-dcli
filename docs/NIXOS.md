# NixOS Integration

dcli can manage a NixOS system without Home Manager: **system-level packages,
services and flake modules go into a generated NixOS module** that your
`/etc/nixos/configuration.nix` imports, while **user applications stay on
`nix profile`**. `dcli sync` reconciles both and finishes with
`nixos-rebuild switch`, so the workflow feels imperative but the state is
declarative.

```
~/.config/dcli/                         /etc/nixos/configuration.nix
├── hosts/nixnix.nix                      imports = [ …/dcli/nixos/dcli-system.nix ];  ← once
│     nix.nixos_enabled = true                     │
│     nix_packages = [ … ]        (nix profile)    │  generated by dcli
│     nixos = { system_packages, config }          ▼
├── modules/<name>/module.nix     ~/.config/dcli/nixos/
└── nixos/                        ├── dcli-inputs.nix   (getFlake bindings, pinned)
                                  └── dcli-system.nix   (imports + systemPackages + raw modules)
```

## Setup

On the installed NixOS system, inside your existing dcli config:

```bash
dcli init --nixos
```

This never overwrites existing files. It creates `hosts/<hostname>.nix` if
missing, generates the `nixos/` files, and prints the one line to add to
`/etc/nixos/configuration.nix`:

```nix
imports = [ /home/<user>/.config/dcli/nixos/dcli-system.nix ];
```

Then:

```bash
dcli validate
dcli sync --dry-run
dcli sync
```

`dcli sync` on a host with `nix.nixos_enabled = true`:

1. reconciles `nix_packages` / flake packages with `nix profile`
2. runs enabled module hooks (e.g. the KineticWE dev build)
3. regenerates `nixos/dcli-inputs.nix` + `nixos/dcli-system.nix`
4. runs `sudo nixos-rebuild switch`

Use `dcli sync --no-system` to skip step 4.

> The generated files must be readable by root during evaluation. Keep
> `~/.config` world-readable (the default), or the nix daemon cannot read
> `dcli-system.nix`.

dcli keeps installed-package state per host under
`~/.config/dcli/state/hosts/<hostname>/`, so a home partition shared between
several machines never leaks package state from one host into another.

## Host config

```nix
{ system, pkgs }:

{
  host = "nixnix";

  nix = {
    enabled = true;
    nixos_enabled = true;        # sync ends with nixos-rebuild switch
    nix_profile_enabled = true;  # user apps via nix profile
    home_manager_enabled = false;
  };

  # User applications → `nix profile add`
  nix_packages = [ "firefox" "helix" "ripgrep" ];

  # System side → environment.systemPackages in dcli-system.nix
  nixos = {
    system_packages = [ "wireguard-tools" ];

    # Raw NixOS module text: services, programs.*, systemd units, portals…
    config = ''
      { pkgs, ... }: {
        services.printing.enable = true;
        programs.ccache.enable = true;
        nix.settings.extra-sandbox-paths = [ "/var/cache/ccache" ];
      }
    '';
  };

  # Flakes: pinned getFlake bindings for the system module
  nix_flakes = {
    kineticwe = {
      url = "git+file:///home/don/Projects/kineticwe";
      # rev = "0123456789abcdef0123456789abcdef01234567";  # pin a commit
      nixos_module = true;   # import <flake>.nixosModules.default
    };
  };
}
```

### Modules

Every enabled `.nix` module can contribute the same `nixos` block and
`nix_flakes` entries; `dcli` merges them into the generated module (conflicting
flake input declarations for the same name are an error):

```nix
{ pkgs, system }:

{
  description = "Example system-level module";

  nixos = {
    system_packages = [ "docker" ];
    config = ''
      { pkgs, ... }: {
        virtualisation.docker.enable = true;
      }
    '';
  };
}
```

`nixos.system_packages` and `nixos.config` are supported in Nix host files
(`host.nix`), Nix module files (`module.nix`) and directory manifests
(`module.yaml`). Plain `packages = [ … ]` is *not* installed on NixOS;
`dcli validate` warns and points at `nixos.system_packages` / `nix_packages`.

## Flake inputs (`nixos_module`)

`nix_flakes` entries with `nixos_module = true` are written to
`dcli-inputs.nix` as `builtins.getFlake "<url>[?rev=…]"` and imported as
`dcliInputs.<name>.nixosModules.default`:

- `url` + `rev` — reproducible, pinned commit.
- `url` + `ref` — branch/tag; re-resolved at every evaluation.
- `url` only — follows the flake source's default (for a local checkout:
  the current HEAD, including uncommitted changes to tracked files).
- `follows` is **not supported** for system inputs (`builtins.getFlake` has no
  `--override-input`); dcli errors if one is declared.

`nix_flakes` entries without `nixos_module` are only used by `nix_packages`
(`"<input>#<attr>"`) on the profile side.

## Commands

| Command | Description |
|---|---|
| `dcli build` / `dcli build switch` | regenerate + `nixos-rebuild switch` |
| `dcli build boot` | regenerate + `nixos-rebuild boot` |
| `dcli build test` | regenerate + `nixos-rebuild test` |
| `dcli build build` | build the system without activating |
| `dcli build dry` | `nixos-rebuild dry-build` |
| `dcli build rollback` | switch to the previous generation |
| `dcli build update` | `nixos-rebuild switch --upgrade` |
| `dcli build status` | integration status, pins, drift |

`dcli build` only exists on NixOS and requires `nix.nixos_enabled = true`.
It always regenerates the module first, so manual `nixos-rebuild switch`
invocations can be replaced by `dcli build switch`.

### Imperative installs

```bash
nix profile add nixpkgs#firefox     # works immediately (no dcli involved)
dcli install firefox                # nix profile add + hint to declare it

dcli install --system wireguard-tools
# appends to ~/.config/dcli/nixos/system-packages.yaml; apply with dcli sync
dcli remove --system wireguard-tools
```

Declaring the package in `nix_packages` (user) or `nixos.system_packages`
(system) is what makes `dcli sync` converge and `--prune` remove strays.
Packages installed only with raw `nix profile add` are left alone unless
`--prune` is used (dcli matches profile element names).

## KineticWE example (dev machine)

The repository ships a `kineticwe-dev` module (kept in the dcli config, not in
this repo) that:

- builds `git+file://$HOME/Projects/kineticwe` (HEAD, dirty-aware) into the
  **nix profile** (`#kinetic-we`, `#noctalia`, `#session`) on every `dcli sync`,
  so only changed code needs rebuilding;
- declares the `noctalia-greeter` flake pinned to a revision and enables the
  Noctalia login greeter (`greetd`) **once**, on the first sync after the
  module is enabled (`KWE_GREETER=0` opts out) — reboot afterwards;
- registers a `KineticWE` Wayland session that launches
  `~/.nix-profile/bin/start-kineticwe`, which prefers the profile's freshly
  built compositor and shell;
- enables `programs.ccache` + `/var/cache/ccache` so the KineticWE nix
  derivations only recompile changed translation units.

Typical loop:

```bash
cd ~/Projects/kineticwe && edit code
dcli sync            # rebuild → profile upgrade → nixos-rebuild switch
# log out and back in for compositor changes
```
